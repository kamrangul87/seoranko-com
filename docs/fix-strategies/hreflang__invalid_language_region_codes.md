# hreflang__invalid_language_region_codes

Status: READY
Topic: 47 of the issue register
Tier: A
Shared facts: `_hreflang_shared_facts.md`
Research title: hreflang__invalid_language_region_codes (topic 47).
Research date: 2026-09-15

---

## what's actually wrong

An hreflang value is not a code Google accepts.

## threshold

Google's accepted set is **narrower than BCP 47**, so this cannot reuse topic
34's grammar validator.

| Condition | Source | Severity |
|---|---|---|
| region supplied without a language (`US`) | G12 | high — invalid |
| language not ISO 639-1 | G10 | high |
| region not ISO 3166-1 Alpha-2 | G11 | high |
| `en-UK` or any reserved region (`EU`, `UN`, `UK`) | G13, G14 | high — Google ignores that portion |
| `es-419` | G15 | high — **valid BCP 47, unsupported by Google** |
| inverted order (`US-en`) | G9 | high |
| duplicate locale code pointing at conflicting URLs | G4 | high |
| `x-default` with an accompanying language code | G20 | moderate — it represents no language |
| ISO 15924 script code (`zh-Hant`, `zh-Hans`, `zh-Hans-US`) | G16 | **none.** Supported |
| `x-default` absent | G19 | **none.** Recommended, not required |

## detect

Validate against the composed rule, not a single standard:

1. Split on `-`. First subtag must be ISO 639-1.
2. A second subtag may be an ISO 15924 script code (G16) or an ISO 3166-1
   Alpha-2 region (G11).
3. Where a script code is present, a third subtag may be a region
   (`zh-Hans-US`).
4. Reject Google's stated exclusions explicitly: reserved regions `EU`, `UN`,
   `UK` (G14) and `es-419` (G15).
5. `x-default` is a permitted literal value with no language semantics (G20).
6. Collect codes from all three declaration methods (G1) and check for
   duplicate codes with conflicting targets.

**Two validator failure modes, both real:**
- grammar-only (BCP 47) validation **passes** `es-419` and `en-UK` — wrong
- hardcoded-list validation **fails** `zh-Hans-US` — also wrong

The rule above avoids both. ISO table versions and verified-on dates live in
`_hreflang_iso_code_tables.md` (same maintenance pattern as the topic 35
requirement table).

## fix

- **`en-UK` → `en-GB`** (G13) — deterministic, Google names the correct form.
- **inverted order (`US-en` → `en-US`)** — deterministic where both subtags
  are individually valid.
- **case normalisation** to `language-REGION` convention (G11) — safe.
- **region without language** — `human-review`. Which language was intended is
  unknowable from `US` alone.
- **`es-419`** — `human-review`. The correct replacement depends on which
  Spanish-speaking markets are targeted, and that is a business decision.
- **`x-default` with a language code** — remove the language code.
  Deterministic (G20).
- **duplicate code with conflicting targets** — `human-review`. Which target
  is intended is intent.

## postcondition

Live: every hreflang value in the served response validates against the
composed rule, and no code appears twice with conflicting targets.

## idempotent?

Yes.

## risk / blast radius

Generated by an i18n helper — a fix applies to every localized page. A wrong
code change routes real users to the wrong locale.

## rollback

Revert.

## verdict

`auto-fixable` for: `en-UK`→`en-GB`, inverted subtag order, case
normalisation, and removing a language code from `x-default`.

`human-review` for: region-without-language, `es-419`, and duplicate
conflicting codes.

## false-positive guards

| # | Guard | Action |
|---|---|---|
| 1 | Validated against BCP 47 grammar only | passes `es-419` and `en-UK`. Validator is wrong (G14, G15) |
| 2 | Validated against a hardcoded locale list | fails `zh-Hans-US`. Validator is wrong (G16) |
| 3 | `x-default` treated as an invalid language code | it is a permitted literal (G17, G20) |
| 4 | Script codes flagged as invalid | supported (G16) |
| 5 | `x-default` absent | not required (G19). Never raise |
| 6 | Codes collected from HTML only | check all three methods (G1) |
| 7 | Lowercase region (`en-gb`) | matching is case-insensitive; report as a convention issue at most, never high severity |
| 8 | ISO table snapshot older than its verified-on date, or undated | do not raise from it. Same rule as topics 35 and 39 |

### Explicitly rejected

- **Reusing topic 34's BCP 47 validator.** Google's set is narrower (G14,
  G15).
- **Auto-replacing `es-419`.** The correct target markets are a business
  decision.
- **Guessing a language for a region-only code.**
- **Treating `x-default` absence as a defect.** G19.

## fixture

`hreflang="US"`; `hreflang="en-UK"`; `hreflang="es-419"`; `hreflang="US-en"`;
`hreflang="zh-Hans-US"`; `hreflang="x-default"` alone; `hreflang="x-default"`
with `hreflang="en"` on the same link; `hreflang="en-gb"`; two `hreflang="de"`
links with different targets; no `x-default` anywhere.

CI asserts: `human-review` for the first, third and ninth; auto-fix for the
second, fourth, seventh and eighth; **nothing** for the fifth, sixth and
tenth.
